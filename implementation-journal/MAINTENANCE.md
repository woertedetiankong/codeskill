# Maintaining This Skill

Guidance for editing the skill itself. Nothing in this file is loaded at runtime; do not reference it from SKILL.md.

- When changing SKILL.md or the references, validate with isolated subagents or thread forks if the environment supports them. Give each agent a realistic scenario and the skill artifact, not your expected answer. If no subagent facility is available, skip this step and note the limitation.
- Each rule lives in exactly one place: creation conditions and triggers in SKILL.md; formats, field definitions, and deep guidance in `references/`. Before adding text, search the other files for restatements of the same rule and consolidate instead of duplicating.
- `agents/openai.yaml` is metadata for a non-Claude harness; Claude Code ignores it. Keep it only while the skill is used with that harness.
- `.claude-plugin/plugin.json` makes this folder a Claude Code plugin; the repo root's `.claude-plugin/marketplace.json` lists it. Claude Code also loads it as a plugin (`implementation-journal@skills-dir`) whenever the folder sits in `~/.claude/skills/`. Everything the plugin uses must stay inside this folder: marketplace installs are copied to a cache, and `../` paths do not load.
- `hooks/` holds the Claude Code hook scripts; `hooks/hooks.json` registers them through the plugin. hooks/README.md keeps a manual settings.json snippet only for setups where the plugin is not loaded; never both, or every hook runs twice. Do not add a `paths:` frontmatter field to SKILL.md: it limits auto-loading to sessions that touch matching files, which would stop the skill triggering before a dossier exists. Keep their journal-file paths and validator invocation in sync with SKILL.md defaults and the script.
- `scripts/validate_journal.py` mechanically mirrors rules that live in SKILL.md and `references/` (handoff frontmatter and sections, handoff read budget, restart-verify shape, relative-date bans, log entry format, session-entry fields, template placeholders, report fields, word limits, and banned text). When editing those rules, update the script's checks in the same change, and rerun it against one known-good and one deliberately broken fixture dossier before shipping.
- `scripts/render_report.py` draws every field in references/report.md. Adding or renaming a report field means changing report.md, report-example.json, the validator, and the renderer in the same change, then validating and rendering report-example.json in a scratch dossier. The renderer also writes `index.html` in any folder holding dated dossiers, draws `flow` as SVG with its own small layout code (keep the node and edge limits in the validator), and runs read-only git commands for the `code` block; `commands/report.md` (the Claude Code command) only runs it with `--open`, so keep its flags in sync.
